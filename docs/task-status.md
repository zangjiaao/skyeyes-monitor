# 任务状态页

状态页以执行进度和等待原因作为首要信息。保留原页面框架，将数据源配置和分组累计数收进次要区域。

## 页面信息顺序

主页面仅展示任务概览与历史列表：

- 任务范围、状态、用时与检索进度条。
- 接口返回、命中、入库、可投递四项数字。
- 各来源的状态、进度条、返回数与新增数。
- 可筛选、分页的任务历史。

「执行记录」或历史行的「详情」打开任务详情，分为执行记录、异常与等待、任务信息三个页签。长错误、过滤原因、查询表达式与时间窗口在详情中查看；主页面只在异常时显示简短提示。
「环境」单独查看计划、配置与分组统计。主页面不展示大段辅助说明。

默认每 10 秒刷新，页面在后台时暂停轮询；可取消自动刷新或立即刷新。执行记录仅在详情页签打开时请求。刷新失败保留上次数据。

## 如何理解进度

一条检索条件可能包含多页结果。进度条显示“已完成检索条件 / 启动时计划条件”，不表示时间百分比，也不包括最终 Excel 汇总和邮件发送。
X 按检索词计算，Google News 按检索词和版本展开，GDELT 按实际打包条件计算。

来源阶段区分：准备、等待请求间隔或限流重试、查询上游、读取响应和校验命中、处理翻译/评分及入库、延后续跑、完成、失败、取消。

- 未来才唤醒的任务是正常等待。
- 超过计划唤醒或入队时间 15 分钟仍未执行，提示可能卡住。
- 正在运行但租约已过期，提示可能被中断。
- 超过采集截止时间或收尾宽限时间时，提示等待定时维护。定时维护按小时执行。
- 已结束的任务不会因遗留批次状态被误判为仍在执行。

“恢复”仅用于仍可恢复的运行。它可能重新领取正在执行的来源，页面会说明这一点。最终状态为未完成的历史任务，应从数据页重新发起一次指定分组采集。

## 执行结果

累计返回、命中、过滤、去重可能包含同一页重抓的数据；过滤还包含来源端命中校验，不能把所有指标直接相减。
实际入库与当前可投递数量另从记录表统计。

任务完成指采集与收尾完成，不保证 AI 翻译/评分或邮件全部成功。翻译或评分失败的已完成任务仍出现在“需要关注”，详情中单独列出错误。

## 数据与兼容

`0019_run_observability.sql` 新增启动范围快照、来源条件进度/阶段/最近活动，以及 `run_events` 执行记录表。
`npm run dev` 会自动应用本地迁移。生产按现有 CI 迁移流程更新。
旧任务能继续查看原有批次统计，但不能补写启动快照、上游返回量或历史查询事件。

记录包含目标名和查询条件，不保存请求密钥、请求头或完整接口响应正文。新记录保存在 D1 中，开发服务重启和页面刷新后仍可查看。诊断事件写入失败会记录警告，不阻止采集。

## API

- `GET /api/runs?page=1&status=all`：每页 20 个任务，返回 total/page/pageSize，包含汇总进度和范围快照。
- `GET /api/runs/:id`：来源进度、阶段、卡住原因、实际入库统计，以及最近 20 条 AI 异常记录。
- `GET /api/runs/:id/events?before=<id>`：按单调事件 ID 向前翻页，每页 50 条；省略 before 返回最新记录。

API 沿用管理后台的 Access 身份与管理员校验。
